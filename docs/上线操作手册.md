面向场景：链动小铺售卖的卡密因特殊原因需要批量退款，让用户自助登记信息，你核实后人工打款。

- 用户端：填订单号、卡密/兑换码、联系方式、退款金额、退款原因、收款码截图 → 提交
- 用户端：凭「订单号 + 联系方式后 4 位」查询退款进度（只显示脱敏信息）
- 管理端：`/admin` 固定密码登录，列表筛选、搜索、查看收款码、标记已退款 / 驳回、批量操作、导出 CSV

> 上线过程中踩到并已修复的两个坑，记在这里便于日后重建环境时避免：
> 1. **环境变量被写入 UTF-8 BOM**：用 PowerShell 的 `Set-Content` 写值再喂给 `vercel env add`，会在值首部带上不可见的 BOM，导致连接串被判定为「非法 URL」、后台密码比对失败。必须用 Node 的 `writeFileSync`（默认不写 BOM）或网页表单直接粘贴。
> 2. **Vercel 新项目默认开启 Deployment Protection**：会导致外部用户打开链接时被要求登录 Vercel 账号。需在项目 Settings → Deployment Protection 关闭，或调用 API 把 `ssoProtection` 置为 `null`。

## 一、本项目已经做好的事

| 能力 | 说明 |
| --- | --- |
| 同订单号只能登记一次 | 数据库唯一索引 + 应用层双重校验，重复提交返回明确提示 |
| 服务端权威校验 | 订单号 `LD…`、兑换码 `XXXX-XXXX-XXXX`、金额、枚举范围都在后端再校验一次 |
| 收款码压缩上传 | 手机原图在浏览器端压到长边 1280px / JPEG，通常 150~500KB，二维码依然可扫 |
| 收款码存云对象存储 | 压缩后直接上传 Vercel Blob，数据库只存一个地址；对象键带 16 字节随机串，无法枚举猜测 |
| 收款码仅管理员可见 | 后台通过 `/api/admin/receipts/[id]`（需登录）代理读取，原始 Blob 地址不下发给任何前端 |
| 删除记录即清除图片 | 后台删除登记记录时，会把对象存储里的收款码一并删除，避免敏感图片长期留存 |
| 上传失败自动兜底 | 对象存储不可用时自动退回「base64 存数据库」，用户侧无感知，登记不会失败 |
| 后台密码保护 | HMAC 签名 Cookie，12 小时过期，连续输错 8 次锁定 10 分钟 |
| 防刷 | 提交接口按 IP 限流（12 次/分钟）+ 蜜罐字段；上传接口另有 20 次/分钟限流 |
| 进度查询防冒领 | 必须「订单号 + 联系方式后 4 位」同时匹配，返回内容全部脱敏 |
| CSV 导出 | 带 UTF-8 BOM，Excel 双击不乱码；含公式注入防护 |
| 自检接口 | `/api/health` 可直接看数据库、对象存储、密码是否就绪（不泄露任何变量内容） |

## 三、正式上线（Vercel + Neon 免费数据库 + Vercel Blob 对象存储）

### 1. 建云数据库（Neon）

1. 打开 <https://console.neon.tech> 注册/登录（Google 或 GitHub 账号即可，免费版够用）。
2. 点 **New Project**，名字随意（例如 `refund`），Region 选 **Singapore** 或 **US West**（离用户近更快）。
3. 创建完成后，在项目的 **Connection string** 区域选择 **Pooled connection**，复制整串，形如：
   ```
   postgresql://user:password@ep-xxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```
   这串里包含数据库密码，**不要发到群里或截图给别人**。

> 已兼容其他 Postgres（含 Supabase）：把连接串填进 `DATABASE_URL` 即可，应用会自动建表，无需手工执行 SQL。

### 2. 部署到 Vercel

**方式 A：网页导入（推荐，不需要给别人任何密码）**

1. 把本项目推到你的 GitHub 仓库：`git remote add origin <你的仓库地址>` → `git push -u origin main`。
2. 打开 <https://vercel.com/new>，用 GitHub 登录，选中这个仓库，点 **Import**。
3. Framework 会被自动识别为 Next.js，Build Command / Output 都不用改。
4. 展开 **Environment Variables**，填 3 个（详见下一节）后点 **Deploy**。
5. 一两分钟后拿到线上地址，形如 `https://refund-xxx.vercel.app`，这就是发给用户的链接。

**方式 B：命令行部署**

```bash
npm i -g vercel
vercel login          # 浏览器授权
vercel --prod         # 首次会问几个问题，全部回车用默认值
```
环境变量用 `vercel env add DATABASE_URL production` 依次添加，或部署后在网页 Settings 里加。

### 3. 需要的环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | ✅ | Neon 的 Pooled 连接串。**不配置就是本地文件存储，线上会看到红色告警条** |
| `BLOB_READ_WRITE_TOKEN` | ✅ | 收款码对象存储令牌。在 Vercel 创建 Blob store 时会自动写入，无需手填；缺失时自动退回「图片以 base64 存数据库」，功能不受影响但会占数据库空间 |
| `ADMIN_PASSWORD` | ✅ | 管理后台密码，建议 16 位随机串，例如 `Kf7Qm2Zp9Lx4Rt8W` |
| `AUTH_SECRET` | ✅ | 登录态签名密钥，随便一串长随机字符；改掉它能让所有已登录设备立即失效 |
| `NEXT_PUBLIC_SITE_NAME` | 可选 | 页面标题，默认「卡密退款登记」 |
| `NEXT_PUBLIC_DEADLINE_NOTE` | 可选 | 例如「请于 10 月 12 日 24:00 前完成登记，逾期不再受理」 |
| `NEXT_PUBLIC_SUPPORT_CONTACT` | 可选 | 客服微信/QQ，会显示在成功页 |

改完环境变量必须 **Redeploy**（Deployments → 最新一条 → ⋯ → Redeploy）才会生效。

### 3.5 建收款码的对象存储（本项目已建好，重建环境时才需要）

```bash
npx vercel blob create-store refund-receipts --access public -e production -r sin1 -y
# 成功后会输出 store id，并自动把 BLOB_READ_WRITE_TOKEN 写进项目生产环境变量
```

> 说明：`--access public` 是必须的（Vercel 的 private store 需要 Pro 套餐）。
> 本项目用「对象键带 16 字节随机串 + 后台鉴权代理读取」来保护收款码，前端永远拿不到 Blob 原始地址。
> 若日后升级到 Pro，可把 `lib/storage.ts` 的 `access` 改为 `'private'` 并使用签名 URL 读取。

### 4. 上线后立刻做的自检

```bash
# 1) 看数据库、对象存储、密码是否就绪
curl https://你的地址/api/health
#    期望： "mode":"postgres"，"receiptStorage":"blob"，hasAdminPassword=true

# 2) 用线上地址跑一遍完整流程自测
set SMOKE_BASE=https://你的地址
set SMOKE_PASSWORD=你设置的ADMIN_PASSWORD
node scripts/smoke.mjs
#    期望：29 项全部 ✅
```

浏览器再手工确认三件事：

1. 打开首页，随便填一单（金额 96，收款码随便传张图），看到「登记成功」。
2. 打开 `/admin`，用 `ADMIN_PASSWORD` 登录，能在「待人工退款」里看到刚提交的单，收款码能点开放大。
3. 点「标记已退款」，然后去 `/query` 用「订单号 + 联系方式后 4 位」查到状态变成「已退款」。

## 五、以后要改东西 / 重新部署怎么办

改完代码后，在本项目目录下执行：

```bash
npx vercel --prod --yes        # 直接发布到现有线上地址，约 40 秒
```

要改密码或加配置：

```bash
npx vercel env rm ADMIN_PASSWORD production --yes    # 删旧值
npx vercel env add ADMIN_PASSWORD production         # 粘贴新值后回车
npx vercel --prod --yes                              # 必须重新部署才生效
```

> ⚠️ 用命令行加环境变量时，**不要**用 PowerShell 的 `Set-Content`/`Out-File` 生成输入文件
> （会引入 BOM 导致值被污染，本项目已踩过一次），直接在终端里手动粘贴，或用 Vercel 网页
> Settings → Environment Variables 添加更稳妥。

只想换个密码，也可以直接在 Vercel 网页改环境变量后点 Redeploy，效果一样。

## 六、日常使用流程建议

1. **发布登记入口**：把线上地址发到店铺公告、客服自动回复、QQ/微信群。建议话术：
   > 因系统原因需为部分卡密订单办理退款，请在本页登记：<链接>（需填订单号、卡密、联系方式并上传收款码）。按登记顺序核实打款，请勿重复提交。
2. **核对待办**：打开 `/admin`，默认就在「待人工退款」列表，左侧卡片是各状态数量。
3. **逐单核实**：点「核实详情」看收款码 → 回到链动小铺后台比对订单号和金额 → 用微信/支付宝转账 → 回来点「确认已退款」，可顺手填备注（用户在查询页能看到）和转账单号。
4. **异常单处理**：订单号对不上、卡密已被他人使用、非本店订单，点「驳回」并写清原因。
5. **收尾**：全部处理完点「导出 CSV」留档，里面含金额、备注、打款时间、提交 IP。

## 七、收款码图片存在哪、怎么清理

- **存哪**：用户提交时，浏览器先把截图压到 1280px / JPEG，再直接上传到 **Vercel Blob** 对象存储
  （store `refund-receipts`），数据库里只保存一个地址和对象键。数据库因此很轻，几百单也只有几百 KB。
- **谁能看**：只有登录后的管理员能通过 `/api/admin/receipts/[id]` 看到图片，接口会服务端代理读取对象，
  不会把 Blob 原始地址下发到浏览器；未登录访问返回 401（已纳入自测）。
- **删记录会不会删图**：会。后台「核实详情 → 删除这条记录」时，对象存储里的对应图片会一起删除。
- **清理自测/放弃提交留下的图片**：运行

  ```bash
  node scripts/cleanup-blob-orphans.mjs --dry   # 先看有哪些孤儿图片
  node scripts/cleanup-blob-orphans.mjs         # 确认后删除
  ```

  脚本会列出对象存储里所有收款码，减去数据库仍在引用的，剩下的就是孤儿。

> 关于安全等级：Vercel 的 **private** Blob store 目前需要 Pro 套餐，本项目用的是 public store，
> 因此依赖「随机对象键 + 后台鉴权代理」来保护。对收款码这类图片来说这个强度是可接受的
> （URL 含 16 字节随机串，无法枚举；页面上也不暴露该地址）。如果你升到 Pro，可以把
> `lib/storage.ts` 里的 `access: 'public'` 改成 `'private'` 并把读取改为签名 URL，安全性会更高。

## 八、需要留意的风险

- **Vercel 免费版（Hobby）条款**：官方规定 Hobby 套餐仅限个人非商业用途，你这属于经营场景，长期建议升 Pro（约 $20/月）；短期应急一般不会有人管，但请知悉。
- **管理密码已经在聊天里出现过**：建议你按第五节的方法改成只有自己知道的密码（改完记得重新部署）。
- **数据库连接串是最敏感的东西**：它写在本地 `.env.local`（已被 Git 忽略，不会提交）。不要把 `.env.local` 内容发到群里或截图。
- **不要在公开渠道暴露 `/admin`**：密码保护已经有了，但建议不要在群里贴后台地址。
- **收款码属于敏感信息**：只用于本次打款，打完建议集中清理。删除后台记录会自动删掉对象存储里的图片；批量清理用 `node scripts/cleanup-blob-orphans.mjs`，或直接在 Neon SQL Editor 执行 `DELETE FROM refunds WHERE status='refunded';`（这条只删数据库记录，图片需再用上面脚本清一次）。
- **退款金额以订单实付为准**：用户自填的金额只作参考，你核实链动小铺后台的实付金额（96 / 133.9 等）后再打款。
- **数据备份**：Neon 免费版有历史恢复能力；也可以定期点「导出 CSV」自己存一份。
